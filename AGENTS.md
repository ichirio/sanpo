# Agent / contributor instructions

This repository **is the R package** (`DESCRIPTION` is at the root). The
package name `sanpo` is **provisional**: the concept comes first ("plots
often used in claims / database research that other packages cannot make
well, as one family") and the name will be chosen later. Keep the package
name out of function, class and argument names so that a rename only
touches `DESCRIPTION`, `README.md`, the docs and the repository.

`CONTRIBUTING.md` has the workflow; `DECISIONS.md` lists the provisional
design choices and the open questions.

## Design -- do not break

- **One data contract: the journey.** Episode data -> `jn_sequence()` ->
  a `class_journey` S7 object (`@sequence`, `@states`, `@meta`,
  `@n_persons`). Every plot and table reads a journey. The class validator
  keeps the invariants; do not bypass it.
- **Layers by prefix.**
  - `jn_*`: data verbs and derived data (`jn_simulate()`, `jn_sequence()`,
    `jn_states()`, `jn_flows()`, `jn_tree()`).
  - `plot_*`: figures (`plot_sankey()`, `plot_sunburst()`, `plot_icicle()`),
    plus `scale_fill_journey()` and `theme_journey()`.
  - `tbl_*`: tables as data frames (`tbl_pathways()`).
- **States dictionary is the source of order and colour.** Factor levels =
  node order; unused levels = empty nodes (kept, `drop = FALSE`); one colour
  per level through `scale_fill_journey()` in every figure.
- **ggplot2-native static output first.** Plot functions return an ordinary
  `ggplot` (theme, facets, `ggsave()` work). No htmlwidgets or JavaScript;
  interactive converters may come later as optional extras.
- **Aggregate before drawing.** Sankey ribbons are drawn from aggregated
  flows, never one line per patient, so 100k patients stay fast.
- **Light dependencies.** `Imports:` is `cli`, `ggplot2 (>= 3.5.0)`,
  `rlang`, `S7` and base packages. Anything new goes to the maintainer first
  with a one-line reason.
- **No real data and no real code masters.** Examples and tests use
  `jn_simulate()` or small inline data frames. Codes in synthetic data are
  fictional; code-to-class maps are brought by the user.
- **ASCII-only R code** (use `\uXXXX` escapes for Japanese text).
- **`NAMESPACE` and `man/` are generated by roxygen2**; commit them.

## Resource rules (local work)

- One R process at a time; no parallel R sessions or parallel agents.
  Keep R sessions short.
- Install into a private library (`R_LIBS_USER`) and point `R_USER`, `HOME`
  and `R_USER_*` at a private work folder; never write to the real home or
  the root of `$TEMP`.
- `R CMD check --as-cran` once, just before the pull request.

## Workflow

1. One issue -> one branch off `main` -> one pull request.
2. Change `R/`, `tests/testthat/` and the roxygen docs together.
3. Run `roxygen2::roxygenise()`, the tests, `lintr::lint_package()` and,
   once at the end, `R CMD check --as-cran` (target: 0 errors / 0 warnings
   / 0 lints).
4. Bump the **fourth** version number in `DESCRIPTION` and add a line to
   `NEWS.md`.
5. Open the pull request against `main`.
